> (Machine translation. Refer to the English pages for the authoritative text.)

**UNDER NIGHT IN-BIRTH II Sys:Celes** (Steam, `uni2.exe`) 用のトレーニング・利便性向上 MOD です。

`dinput8.dll` のプロキシとして読み込まれ、ゲームの Direct3D 9 レンダラー内に Dear ImGui のオーバー
レイを描画します。

## オンラインについて

**この MOD には、オンラインで有利になるように作られた機能はひとつもありません。**

シミュレーションを変えうるトレーニング機能はすべてオフライン専用です。フレーム送り、停止、キャラ
クターの手動操作、ダミースクリプト。判定にはゲーム自身の P2P 通信を使います。直近 3 秒以内に対戦
相手へパケットを送っていれば、これらは動きません。本作は GGPO ロールバックを使っており、対戦中に
シミュレーション状態へ触れると同期ずれを起こします。

オンラインで動くのは外見だけの読み取り専用の機能です。カスタムパレットは Steam 経由でゲームと並行
して送られるため対戦に影響しません。パフォーマンス設定は映像がモニターへ届く経路を変えるだけです。

**パッチセレクターだけは例外で、オフライン専用です。** パッチはシミュレーション自体を変えます。技
テーブルとシステム定数は起動時に一度だけ読まれ、セッション中ずっと残ります。パッチで起動したなら、
どのメニューにいてもオンラインでもそのままです。同じパッチを選んだ相手としか成立しません。**ランク
マッチや、選んでいない相手との対戦では使わないでください。同期ずれを起こします。** 対戦の前に、
インストール版で起動し直してください。

実際の対戦で有利になるものを見つけたら、それは不具合です。報告してください。

## インストール

リリースの zip を `uni2.exe` と同じフォルダーに展開します。

```
<Steam>\steamapps\common\UNDER NIGHT IN-BIRTH II Sys Celes\
```

2 ファイルです。`dinput8.dll` が MOD 本体。`UNI2IMUpdater.exe` は次のバージョンを入れるためのもの
で、単体では何もしませんし、なくても動きます。

ゲーム中に **F1** でオーバーレイ。アンインストールは 2 つとも削除するだけです。

`UNI2_IM.ini` は初回起動時に既定値で `UNI2-IM` フォルダーに作られます。以降は起動のたびに、無い
キーやセクションが既定値で追記され、編集済みの値には触れません。削除すれば既定値に戻ります。各キー
は [The ini file](The-ini-file) にあります。

## Linux / Steam Deck (Proton)

`dinput8.dll` を Windows と同じ場所に置き、Wine に読み込ませる 1 手順を追加します。

1. Steam ライブラリでゲームを右クリック → **プロパティ**。
2. **一般** の **起動オプション** に、この行をそのまま貼ります。

```
WINEDLLOVERRIDES="dinput8=n,b" %command%
```

3. ゲームを起動して **F1**。

これだけです。名前の変更も追加のコピーも要りません。

**理由。** Wine はどの `dinput8.dll` を読むかをプレフィックスの設定で決めるため、この行が無いと
DLL は置かれたまま一度も読まれません。`n,b` は「まずネイティブ、次に内蔵」で、MOD のコピーが読ま
れ、Wine 自身の `dinput8` が MOD の中継を処理し続けます。だからコントローラー入力も動きます。

Proton 9 以降は MOD の `dinput8.dll` に対して既にこれを行うので、この行があっても無害です。古い
Proton では必要です。

Linux では **互換セーフモード** が自動で有効になります。フルスクリーンのリフレッシュ書き換え、電源
スロットリング解除、`Sleep` の差し替えを行いません。`[Compat] WineSafeMode = 0` で戻せます。

何も起きない場合は `uni2.exe` の隣に `UNI2-IM` フォルダーがあるか確認してください。無ければ DLL が
読まれていないので、原因は上の手順です。

## RivaTuner / MSI Afterburner などのオーバーレイ

同じ Direct3D 関数に 2 つのフックエンジンが載ると、片方がもう片方の jump を上書きします。RTSS は
自分の jump を戻すので、そのとき相手のフックが外れます。

この MOD は誰も上書きしません。関数の先頭にある jump の連なりを辿り、その末尾に自分を入れます。
RTSS の作者が third party に求めているやり方です。両方が 1 本の鎖に収まり、読み込み順は関係なく
なります。Steam オーバーレイが問題なく重なるのも同じ変更のおかげです。

まだ問題が出るなら `[Debug] Logging = 1` を設定して 1 回起動してください。`UNI2-IM/Logs` のログに
どのフックで何が起きたかが出ます。RTSS 側は 2 つの設定で解決します。

- **Settings → General → Injection properties → "Use Microsoft Detours API hooking"**
- **ゲームの RTSS プロファイル → Application detection level → None**

## 機能

### オーバーレイ

**F1**。Training、Custom、Config の 3 セクションが 1 つのウィンドウに入っています。ヒットボックス
表示、フレームメーターの凡例、Player Control、Performance、Music、Stages は別ウィンドウです。

テキスト入力中はキーボードがオーバーレイのもので、ゲームには何も渡りません。キー割り当ての取得中も
同じです。

### ヒットボックス表示

**F2**。キャラクターと飛び道具の全ボックスを、ゲーム自身の色で描きます。装飾はエンジンの
`_Exist_NoHantei` フラグで除外しています。

投げ、D シールド、近距離ガードのボックスはありません。ゲームに存在しないからです。投げの判定は、
投げ属性を持つフレームの通常の攻撃ボックスです。

### フレームメーター

**F3**。状態ごとの帯、確定した帯の中のフレーム数、やり取りの合計、そのフレームで有効な無敵を並べた
ステータス行。フレーム有利はゲーム自身の有利フィールドから取っています。

画面下寄りに出て、マウスでドラッグできます。バックバッファーに直接描いているのでオーバーレイの当たり
判定を持たず、上でクリックすると動きます。

### 一時停止とフレーム送り

**F5** で停止、**F6** で 1 フレーム送り、長押しで連続。

停止方法は 2 つ。*Tick stop* はゲームのフレーム全体を止めます (既定)。*Hitstun Stop* はエンジンの
ヒットストップを流用し、メニューは動きますがエフェクトの描画は正しくありません。手法上そうなります。

オートポーズは攻撃、アーマー技、コンボの指定ヒット数で停止し、カウントダウン後に再開できます。

### Player Control

専用ウィンドウ。両サイドの入力をテンキー表記とボタン 4 灯でリアルタイムに表示します。自分のパッド
やキーボードをどちらのキャラクターにも向けられ、ダミーに方向やボタンを保持させたり、数フレームだけ
入力させたり、サイドごとにスクリプトを走らせたりできます。

入力遅延も測れます。実際に押してからそのキャラクターの入力フィールドが変わるまでの実時間です。
キーボードとパッドは専用スレッドで毎秒約 1000 回読んでいます。

### キーボードのサイド

*Config → Keyboard*。キーボードを **1P** と **2P** のどちらにするか選びます。設定済みのキーのまま、
独立したプレイヤーになります。1 台で 2 人が遊ぶローカル対戦向けです。

ゲームはキーボードと 1 番目のコントローラーに同じプレイヤー番号を割り当てるため、ローカル対戦では
同じキャラクターを操作してしまいます。ここでサイドを選ぶと、動くのは **コントローラー** の方です。

オンラインでは何も動きません。

### パレット

どちらのキャラクターの色も、その場で変えられます。色はキャラクターに属するので、クロスオーバーでも
ついてきます。着ていた色は記憶され、次回自動で戻ります。

パレットはゲーム自身の形式である `.pal` ファイルです。`UNI2-IM\Palettes\<キャラクター>` に、名前・
作者・説明とともに保存されます。エフェクトの色もパレットの一部です。

オンラインでは、自分のパレットが Steam 経由で相手に送られます。**See the other player's colours**
で相手側の扱いを決めます。MOD を入れていない相手には何も見えません。

**Palette Nativa** は別物です。ゲーム自身のカラーカスタマイズをオーバーレイから操作します。好きな色
は作れませんが、ゲームが保存し、**すべての** 対戦相手に見えます。

### ボイスとサウンド

キャラクターのボイスや効果音を差し替えます。そのキャラクターだけが変わります。

**Replace** タブでキャラクターを選び **Load voices and sounds**。戦闘ボイス、ストーリー、勝利
セリフ、アナウンス、メニューと選択、共有効果音が出ます。

**Get this voice from UNI...** は、手元の旧作 (`UNIclr.exe`、`UNIst.exe`、`UNIEL.exe` があるフォル
ダー) からボイスを取り込みます。ファイル名の付け方が違うので、両作がサウンドリストに書いているセリフ
本文で照合します。おおよそ 3 分の 2 が一致します。剣、宇津貴、輝夜、久遠、オウガ、泉は UNI にいま
せん。

差し替えは `UNI2-IM\Sounds` の pack に入ります。**Ogg Vorbis を使ってください。** WAV と MP3 は
一度だけ変換してキャッシュします。音声は MOD には同梱されません。

### Player Card

ゲームが対戦相手に公開するカードを編集します。プレートの 4 レイヤーとタイトルです。タイトルは自由
入力で、書いたとおりに相手へ届きます。

### BGM セレクター

**Music** から開く専用ウィンドウ。音楽が鳴る画面はゲーム内の 1 箇所を通るので、どの画面にも別の曲を
割り当てられます。

**Get OST from French-Bread games** は、手元のコピーからサウンドトラックを読み込みます。`UNIclr.exe`
か `UNIst.exe`、`MBTL.exe`、`MBAA.exe` のあるフォルダーを指定してください。曲名とループ位置つきで
入ります。ダウンロードは行わず、音声は同梱されません。

**Browse** は再生可能な全曲の一覧です。**Randomizer** は曲を要求されるたびに一覧からランダムに渡し
ます。曲ごとに **Volume** があり、`UNI2-IM/bgm.ini` に保存されます。100% が録音時の音量で、それ以上
は上げられません。

**Rules** は手動指定です。**Import music** は MP3・OGG・WAV を取り込みます。

### ステージ

メインウィンドウの **Stages**。2 つあります。UNI2 が自分のセレクターから隠しているステージと、手元の
他の French-Bread 作品から持ってきたステージです。

ステージ一覧は起動時に一度だけ読まれるので、ここでの変更は再起動後に反映されます。

隠れているのは 2 つ、**煌朧の祭壇** と **デバッグステージ** (背景なし、グリッドのみ) です。

移植は **Get stages from French-Bread games** から、`MBTL.exe`、`UNIclr.exe`、`UNIst.exe` のある
フォルダーを選びます。MBTL と UNI は UNI2 と同じ形式でステージを持っているので変換は不要です。手元の
コピーから読み、新しいステージとして書き出します。ゲームの既存ファイルは置き換えません。名前は英語
で、サムネイルは元の作品から取ります。

MBAACC は対象外です。背景が 2D のレイヤーで、UNI2 の形式と共通点がありません。音楽は取り込めます。

### Performance

Config から開く専用ウィンドウ。エンジンのフレームペーシングには具体的な問題があります。メッセージ
ポンプと描画が別スレッドで動き、毎フレーム描画側がポンプしか返せないメッセージを待って止まります。
Windows はゲームがバックグラウンドにある間、ミリ秒のタイマー精度を回収します。

3 つの設定と 2 つのプリセット。ウィンドウは **実際に** 効いている値をデバイスから読み返して表示し
ます。**Metrics** タブで計測できます。

### POTATO MODE

Performance ウィンドウのタブ。60 が出ないマシン向けです。

**どの段階でもステージは描画され、映像のサイズは変わりません。**

| 段階 | 描画解像度 | その他 |
|---|---|---|
| Off | ゲームの Display 設定 | なし |
| Balanced | 960x540 | バックバッファーのマルチサンプリング off |
| Potato | **480p / 360p / 240p / 144p** | Character Visual Improvements も off |

**サイズはウィンドウに対する割合ではなく、絶対値です。** 640x360 はウィンドウが 720p でも 1440p でも
640x360 のままで、Direct3D が引き伸ばします。エンジンはいつも通り描くので、位置がずれることはありま
せん。画像が甘くなるだけです。

排他フルスクリーンではサイズが繰り上がります。バックバッファーは実在する表示モードを指定する必要が
あるためです。反映は次にゲームが表示を作り直したときです。**シミュレーションには一切触れません。**

### Improvements

同じウィンドウの逆向きです。ウィンドウより **大きく** 描き、Direct3D が縮めます。

キャラクターとステージは 1280x720 固定の 5 枚のレンダーターゲットに描かれ、そこは変わりません。
スプライトは精細になりません。良くなるのはバックバッファーに直接描かれるもの、HUD、メニュー、合成の
輪郭、MOD のオーバーレイです。スーパーサンプリングであって内部解像度の向上ではありません。

**Sharpening** が同じタブにあり、こちらの方が有用です。40-60% が実用域です。ウィンドウとボーダーレス
専用です。

### Memory debug

既定では無効。`[Debug] MemoryDebug = 1` を設定して **Ctrl+F1**。
